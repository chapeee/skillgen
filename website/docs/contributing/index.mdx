# Contributing

Thanks for helping. This section explains how to set up, what a change must meet, how to
test it, and how to improve these docs. The repository's own
[`CONTRIBUTING.md`](https://github.com/chapeee/skillprinter/blob/main/CONTRIBUTING.md) is the
maintainers' reference; these pages follow it.

## Ground rules in one minute

1. **No framework or domain knowledge in the core.** Router conventions go in `hintpacks/` as
   YAML. Deleting `hintpacks/` must leave a working tool.
2. **No MCP servers, no client installs.** Generated skills run with the AI's built-in browser
   and nothing else.
3. **Code-only generation is the default.** The Playwright probe is optional and only runs
   with `--xy` or `--url`.
4. **Every fact has a source and a confidence. Evidence never reaches a skill.**
5. **No secrets or real personal data**, anywhere: fixtures, tests, logs, examples. Use
   `example.com`, `555-0100` style numbers and obviously fake names.
6. **No command may prompt or wait for input.** An agent runs every command.

## Before you open a pull request

Run all four; CI runs the same.

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest
uv run pytest -m browser      # if you touched fill.js, probe/ or tests/bench/
```

If your change affects generated output, also run the [test bench](./testing.md#3-the-test-bench-in-claude-and-cowork)
in Claude or Cowork, and paste its results table into the pull request.

## Commits and pull requests

- [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`,
  `test:`, `refactor:`, `chore:`. [Gitsmith](./gitsmith.md) can prompt you through them.
- Small commits, one change each.
- Never commit `.skillgendev/secrets/`, `.env` files or Playwright storage states.
- Record design decisions in `docs/decisions.md`.
- If something in the spec is unclear, open an issue and ask before building.
